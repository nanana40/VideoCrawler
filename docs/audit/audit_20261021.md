## 二、新发现问题

### AUDIT-0087【高】5 个第一方文件被写入双重 UTF-8 BOM，py_compile 失败、无法导入
- **根因**：文件头出现两个连续 BOM（bytes 0-5 = `EF BB BF EF BB BF`）；第一个被 Python 当作 UTF-8 签名消费，第二个成为源码首字符 U+FEFF，Python 3.14 拒绝。
- **涉及文件（均已实测）**：
  | 文件 | 首 6 字节 | py_compile |
  |---|---|---|
  | web/main.py（Web 入口） | EF BB BF EF BB BF | ❌ SyntaxError U+FEFF |
  | core/spiders/youtube_spider.py（核心爬虫，78,742B） | EF BB BF EF BB BF | ❌ |
  | core/classify.py（分类器） | EF BB BF EF BB BF | ❌ |
  | core/cdp_cookies.py（CDP cookies） | EF BB BF EF BB BF | ❌ |
  | core/publish/storage.py（发布存储） | EF BB BF EF BB BF | ❌ |
- **影响**：web 服务无法启动；YouTube 爬虫、分类、CDP、发布存储无法导入（直接阻断核心功能）。
- **一句话建议**：用"另存为 UTF-8（无 BOM）"或脚本删除每个文件头多余 BOM（保留 0 或 1 个，规范为无 BOM），再 py_compile 复核。
- **备注**：根目录 `bom_test.py`（20B，内容为字面 `X = 1\nprint(X)\n`）是诊断临时文件，非架构文件，未计入；已纳入 0066 根目录卫生一并清理。

### AUDIT-0088【中】外部批量写入覆盖工作区，download.py 被整体还原（0077/0085/0084 回退）
- **证据**：
  - `core/download.py:531` 回到 `base = file_sorter._output_dir`（私有访问，原 0084 已改为 `get_output_root()`）；
  - `core/download.py:865-870` `_abort_incomplete(reason)` 无 `permanent` 形参、仅 `raise RuntimeError(reason)`（原 0077 已加 permanent 分支）；
  - 全文件 grep `prefetch_cache` / `permanent` / `get_output_root` = **0 命中**（原 0085 已加缓存）。
- **影响**：永久失败（地区锁/合并不完整）又会重试 3 次、每轮双发预取、跨类读私有属性——10-19 修复全部丢失。
- **一句话建议**：先定位并停止覆盖源（IDE 旧缓冲 / 同步工具 / 外部脚本），再重新应用 0077/0085/0084；`utils/file_sort.py:48-53` 的 `get_output_root()` 仍在、可直接复用。

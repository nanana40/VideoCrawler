## 三、新发现优化点（AUDIT-0056～0076，按严重程度排序）

### AUDIT-0056 core/subtitles/processor.py 缺 2 个关键 import，SubtitleProcessor 实例化即 NameError
- **涉及文件**：`core/subtitles/processor.py:29-53`
- **问题**：`__init__` 第 52、53 行使用 `VideoSubtitleEmbedder`、`SubtitleQualityGate`，但 import 列表（止于 :32）未导入二者。
- **证据**：`processor.py:52 self._embedder = VideoSubtitleEmbedder()`；`:53 self._quality_gate = SubtitleQualityGate()`；无对应 import。
- **影响**：走本地 ASR + 烧录路径实例化即抛 `NameError`；当前 Gemini 全托管路径可能未触发，属潜伏崩溃。
- **建议**：补 `from core.subtitles.embedder import VideoSubtitleEmbedder`、`from core.subtitles.quality_gate import SubtitleQualityGate`。

### AUDIT-0057 GUI 内嵌 Web 与独立 watchdog 生命周期冲突，会复活或误杀 GUI
- **涉及文件**：`gui/web_host.py:48-123`；`web/watchdog.py:296-317,351-450`；`gui/main_window.py:486-516`
- **问题**：web_host 在 GUI 进程内跑 uvicorn(8000)；独立 watchdog 进程每 20s 探测 8000 并自动 taskkill / 重启。
- **证据**：watchdog.py:310 `taskkill /F /PID`（_kill_port）；:428,:442,:633 自动 `_start_uvicorn()`；web_host.py:96-123 启动前也 taskkill 占 8000 的 PID。
- **影响**：(a) 关 GUI 后 watchdog 把 web 重新拉起；(b) 内嵌模式下 8000 由 GUI 监听，taskkill 会杀掉整个 GUI。
- **建议**：加 `VC_DEPLOY_MODE`（embedded/standalone）互斥；watchdog 检测到 GUI 进程则退出。

### AUDIT-0058 硬编码弱默认密钥 "VideoCrawler2026" + 绑 0.0.0.0，可未授权远程控制
- **涉及文件**：`gui/web_host.py:27,52`；`web/watchdog.py:43`；`web/main.py:44`
- **问题**：env 未设时回落硬编码 `VideoCrawler2026`，并经 `setdefault` 注入，使 web/main 放弃随机 key；绑定全部网卡。
- **证据**：`web_host.py:27 DEFAULT_API_KEY = os.environ.get(...) or "VideoCrawler2026"`；`:33 host="0.0.0.0"`。
- **影响**：知道该公开字符串即可调 pipeline/publish/restart（含任意 taskkill），LAN/公网未授权控制。
- **建议**：删除硬编码回落，未设则强制随机或报错；默认绑 127.0.0.1，公网仅由隧道暴露。

### AUDIT-0059 video_repo/task_repo 缺 import os/time，关键路径 NameError
- **涉及文件**：`utils/db/video_repo.py:213,456`；`utils/db/task_repo.py:177`
- **问题**：两文件顶部仅 import typing/logger/enums，却调用 `os.path.exists`、`time.time()`。
- **证据**：video_repo.py:213 `os.path.exists(local_path)`、:456 `time.time()`；task_repo.py:177 `time.time()`；均无 import。
- **影响**：is_video_downloaded、过期清理、死信更新等路径运行即 NameError。
- **建议**：两文件顶部补 `import os`、`import time`。

### 【中】

### AUDIT-0060 烧录 deadline 被 stderr 阻塞读架空，静默卡死仍永久挂起
- **涉及文件**：`core/subtitle_render.py:154-166`
- **问题**：deadline 检查（:157）在 `proc.stderr.read(256)`（:162）之前；该 read 阻塞，若 ffmpeg 不输出也不退出，deadline 检查再无执行机会。
- **证据**：subtitle_render.py:162 `chunk = proc.stderr.read(256)`（阻塞）。
- **影响**：60 分钟保底仅在 ffmpeg 持续吐进度时有效，静默卡死仍挂死（AUDIT-0030 修复不完整）。
- **建议**：用 reader 线程 + queue 读 stderr，或 `-progress pipe:1` 非阻塞读。

### AUDIT-0061 磁盘去重用 __file__ 拼 output 路径，打包后失效
